# Stream fixtures

One sanitized SSE sequence per case, JSON Lines. Line 1 is a header object (`_fixture`, `source`,
`log_id`, `model`, `http_status`, `duration_ms`, `note`); the remaining lines are events in wire
order (`message_start` ... `message_stop`, or an `http_error` / `error` / `non_stream_message` /
`attempt` event for the non-happy paths). A `request_shape` line, when present, describes the
request (block types, flags) with no content.

Spec and rendering rules: `docs/vertex-client-stream-events.md`. Replayed by `test/reducer.test.ts`.

## Where they came from

- `source: gateway-log` (cases 01-37): Cloudflare AI Gateway `fleet-vertex` request/response logs,
  pulled read-only with the pinned `cf` CLI (`ai-gateway logs list / get-request / get-response`).
  A streamed response body is stored by the gateway as a reconstructed message with a
  `streamed_data` array of the raw SSE events; those are the events replayed here.
  `created_at` on a log row is the row END time, so a request's start is `created_at - duration`.
- `source: docs` (cases 40-46): hand-written from the official Anthropic streaming docs for cases
  that never appeared in the logs (streaming max_tokens, refusal, pause_turn, mid-stream `error`,
  visible summarized thinking, redacted_thinking, max_tokens cutting a tool_use). Generated by
  `build_docs_fixtures.py`. They prove the reducer handles the spec, not that real traffic looks so.

## Privacy: structure only

Raw bodies contain real prompts and fleet data and were never printed or committed. The sanitizer
(`build_fixtures.py`, run against a temp copy of the logs that was shredded afterwards) keeps only
structure:

- text / thinking / tool-arg content is replaced by placeholders: `"<text 312 chars>"`,
  `"<thinking 0 chars>"`, `"<sig>"`, `"<json ...>"`; tool inputs are reduced to key names,
- ids are replaced by stable unique tokens (`<id:N>`, one per original id, so two parallel tools
  stay distinguishable),
- signatures, citations, URLs, search results and base64 payloads are placeholders,
- error bodies keep type/status and the field path Vertex complained about, not request content.

The test suite expands placeholders (a `<text N chars>` delta becomes N filler chars, etc.) before
replay so length-dependent rendering still gets exercised.

Checks run before commit: a whitelist scan (fixtures may contain only placeholders and structural
names), the fleet leak-detector shape rules (0 matches) and a local sha256 comparison against
`.secret-guard/known-hashes.json` (0 hits). Only counts were printed.

## Regenerating

`python3 build_fixtures.py <raw_dir> <info.json> <rows.json> <out_dir>` needs raw log bodies that are
deliberately not kept in the repo. Treat the committed fixtures as the artifact.
